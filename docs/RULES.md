# Hackathon rules and judging (summary)

Rules: (1) main coding starts after kickoff; (2) open source/public APIs allowed, original work judged; (3) public repo + README with setup; (4) only data/accounts we may use, nothing private in repo or demo; (5) AI assistants allowed, disclose in README; (6) every human can explain the code; (7) fully AI-generated projects without human understanding may be rejected; (8) one project per team, no copies; (9) valid submission earns the keyboard; (10) team agrees IP ownership before submitting; (11) respect everyone; (12) WeMakeDevs decides.

Tracks we enter: Never Merge Broken (Gitar), Stop Flying Blind (Dash0), AI SRE (Radar), Find the Right Talk (Elasticsearch), Merge Forward (inclusive conferences), Best Overall.

| Track | Judges look for | Our evidence (put in docs/evidence/) |
|---|---|---|
| Gitar | Many PRs reviewed all day, project-aware instructions + rules, CI failure auto-fix | PR links, review threads, auto-fix example |
| Dash0 | Traces+logs+metrics, frontend RUM, Agent0/MCP finds and fixes something real, SLO/dashboard | Connected trace, SLOs, dashboard, Agent0/MCP finding and fix |
| Radar | Runs on Kubernetes with Radar, Radar UI+MCP used, AI investigation of a real issue | Workload screenshot, Argo CD deploy, AI investigation |
| Elasticsearch | ES is core data layer; smart hybrid/semantic search | Queries, mappings, aggregations, optional Kibana |
| Merge Forward | Inclusive, accessible conferences | Demo + a11y tests + VoiceOver pass |

Never stage an incident. Investigate whatever actually happens.
Confirmed at kickoff: **submission deadline 5:15 pm MST** (feature freeze 5:00 pm, so only 15 minutes of margin), **team size 3**.
Still to confirm: demo length.
